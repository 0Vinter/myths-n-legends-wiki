The **Research System** is a fully data-driven progression framework that allows mods and datapacks to gate recipes, items, equipment and other content behind customizable research projects.

Each research project can require materials, NPC progression, previous discoveries and random events, allowing authors to create complete research trees without writing additional code.

## Overview
Each research entry represents a discovery that players can complete by providing required materials and waiting for the research process to finish.

**The Research System supports:**
- Categories.
- Rarity.
- Repeatable research projects.
- Custom ingredients.
- Research duration.
- Rank requirements.
- Progress messages.
- Multiple reward types.
- Research prerequisite.
- Random research events.

## Chronicler Interface
Research projects are managed through the **Chronicler**, who serves as the player's researcher throughout the progression system.

**The interface displays:**
- The Chronicler's current rank.
- Experience towards the next rank.
- Current research status.
- Research progress.
- Required materials.
- The active research project.

## File Location
**Research files are stored inside:**
- data/namespace/research/your_research_file.json

**Example:**
- data/mythsandlegends/research/ancient_copper_sword.json

---

## Research File Structure
A research file follows this format:

```json
    {
      "id": "namespace:research_id",
      "name": "Research Name",
      "category":"combat",
      "rarity": "rare",
      "repeatable": false,
      "ingredients": [],
      "research_time": 12000,
      "required_rank": 1,
      "messages": {},
      "rewards": [],
      "required_research":[],
      "random_events":[]
    }
```
## Research ID
The id field defines the unique identifier of the research.

**Format:**
- namespace:research_name

**Example:**
```json
"id": "mythsandlegends:refined_tenebrite"
```
Each research must have a unique ID.

---

**Name:**
- Defines the display name of the research.

**Example:**
```json
"name": "Refined Tenebrite Research Notes"
```

---
## Category
The category field classifies a research project into a specific group, similar to how Minecraft categorizes recipes and advancements.

Categories may be used by the interface or other systems to organize research projects.
**Example:**
```json
    "category": "combat"
```

- Combat
- Armor
- Relic
- Tools
- Misc

---

## Rarity
The rarity field uses Minecraft's built-in rarity system to determine the visual rarity of a research project.

**Supported values are the vanilla rarities:**
- Common
- Uncommon
- Rare
- Epic

**Example:**
```json
    "rarity": "epic"
```

**Common categories include:**
- Common
- Uncommon
- Rare
- Epic
- Legendary

---

## Repeatable
Research projects may optionally be repeatable.

- When enabled, the research can be completed multiple times.
- When disabled, the research becomes permanently completed after being claimed.

**Example:**
```json
    "repeatable": true
```
---

## Ingredients
The ingredients property defines the materials required to begin the research.

**Example:**
```json
    "ingredients": [
        {
            "item": "mythsandlegends:ancient_copper_coin",
            "count": 2
        }
    ]
```
**This requires:**
- 2x Ancient Copper Coin

**Multiple ingredients can be added:**
```json
    "ingredients": [
        {
            "item": "minecraft:diamond",
            "count": 3
        },
        {
            "item": "minecraft:gold_ingot",
            "count": 5
        }
    ]
```

---

## Research Time
The research_time property controls how long the research takes.

The value is measured in Minecraft ticks.

20 ticks = 1 second

**Example:**
```json
"research_time": 12000
```
**Results in:**
- 10 minutes.

---

## Required Rank
The required_rank property defines the minimum NPC rank required for this research to become available.

The Research NPC is only responsible for providing available researches. Once a player starts or completes a research, the progress is stored individually for that player.

**Example:**
```json
"required_rank": 1
```
The Research NPC must have the required skill at rank **number** or higher.

If the NPC is removed or dies, player research progress is preserved.

**Ranks can be used to create progression tiers:**

- Rank 1 -> Basic Discoveries

- Rank 2 -> Ancient Technology

- Rank 3 -> Forbidden Knowledge

## Player Progress

Research progress is stored per player, similar to Minecraft advancements and recipe unlocks.

Each player has independent research data:

**Player A:**


Copper Coin Sword
- ✓ Completed


**Player B:**


Copper Coin Sword
- ✗ Not researched


Research completion is not tied to the Research NPC.

## Messages
Messages allow custom notifications during the research process.

All messages use Minecraft translation keys.

**Example:**
```json
"messages": {
    "start": "research.example.start",
    "ready": "research.example.ready",
    "completed": "research.example.completed"
}
```
**Start Message:**
- Displayed when the research begins.

**Example:**
```json
"start": "research.myths.start"
```

---

**Progress Messages**
- Progress messages are displayed at specific completion percentages.

**Example:**
```json
"progress": [
    {
        "at": 0.25,
        "translationKey": "research.example.progress1"
    },
    {
        "at": 0.50,
        "translationKey": "research.example.progress2"
    }
]
```

## Rewards
The rewards property defines what the player receives after completing the research.

Recipe rewards are delivered through **Research Notes**. Research Notes permanently store every unlocked recipe.
Players must use the notes to permanently learn the contained recipes.

Item rewards are granted immediately when the research is claimed.

**Recipe Example:**
```json
{
    "type": "recipe",
    "id": "minecraft:enchanting_table"
}
```
**Item Example:**
```json
{
    "type": "item",
    "id": "minecraft:enchanting_table"
}
```
**Currently supported reward types:**

- Recipe
- Item

**Recipe Reward:**

- A recipe reward unlocks a Minecraft recipe for the player.
- The Research Notes item must be consumed before the recipe is permanently unlocked.
- After claiming the reward, the recipe becomes permanently available for that player, similar to Minecraft recipe unlocks.

**Item Reward:**

- An item reward gives the player an item directly.

**Multiple Rewards**

- A research can contain multiple rewards.
- The Research Notes will contain all rewards associated with that research.

**Example:**
```json
"rewards": [
    {
        "type": "recipe",
        "id": "mythsandlegends:copper_coin_sword"
    },
    {
        "type": "item",
        "id": "minecraft:diamond"
    }
]
```

## Required Research
The required_research field defines prerequisite research projects that must be completed before the current project becomes available.

**Example:**
- Tenebrite Shard -> Refined Tenebrite -> Noctifer Tenebris

**Example:**
```json
"required_research": [
    "mythsandlegends:refined_tenebrite"
]
```
Multiple prerequisite research projects are also supported.
```json
"required_research": [
    "mythsandlegends:ancient_metalworking",
    "mythsandlegends:refined_tenebrite"
]
```
All listed prerequisite research projects must be completed before this research becomes available.

---

**Complete Example:**
```json
{
  "id": "mythsandlegends:refined_tenebrite",
  "name": "Tenebrite Refinement Research Notes",
  "repeatable": false,
  "category": "material",
  "rarity": "uncommon",
  "ingredients": [
    {
      "item": "mythsandlegends:tenebrite_shard",
      "count": 8
    },
    {
      "item": "mythsandlegends:cursed_core",
      "count": 1
    }
  ],
  "research_time": 12000,
  "required_rank": 1,
  "messages": {
    "start": "research.mythsandlegends.refined_tenebrite.start",
    "progress": [
      {
        "at": 0.25,
        "translationKey": "research.mythsandlegends.refined_tenebrite.progress1"
      },
      {
        "at": 0.50,
        "translationKey": "research.mythsandlegends.refined_tenebrite.progress2"
      },
      {
        "at": 0.75,
        "translationKey": "research.mythsandlegends.refined_tenebrite.progress3"
      }
    ],
    "ready": "research.mythsandlegends.refined_tenebrite.ready",
    "completed": "research.mythsandlegends.refined_tenebrite.completed"
  },
  "rewards": [
    {
      "type": "recipe",
      "id": "mythsandlegends:refined_tenebrite"
    },
    {
      "type": "item",
      "id": "minecraft:experience_bottle",
      "count": 4
    }
  ],
  "required_research": [],
  "random_events": [
    {
      "type": "distraction",
      "chance": 0.02
    },
    {
      "type": "focused",
      "chance": 0.02
    }
  ]
}
```

## Random Events
Research projects may define random events that can occur while the Chronicler is researching.

**Example:**
```json
"random_events": [
    {
        "type": "breakthrough",
        "chance": 0.04
    },
    {
        "type": "mistake",
        "chance": 0.03
    }
]
```

## Translation File
Research messages must be added inside the mod language file.

**Location:**
- assets/namespace/lang/en_us.json

**Example:**
```json
{
  "research.mythsandlegends.ancient_copper_sword.start":
  "You started researching the Copper Coin Sword.",

  "research.mythsandlegends.ancient_copper_sword.ready":
  "The research is complete!"
}
```

---

## Developer Notes
- Research files are completely data-driven.
- Modpacks can add custom researches without modifying code.
- Multiple researches can unlock the same type of content.
- Translation keys should always be used instead of hardcoded messages.
- Research projects support prerequisite chains.
- Research projects support random research events.
- Research categories and rarity are entirely data-driven.
- Research Notes permanently unlock recipe rewards.
- Research projects may be repeatable.
